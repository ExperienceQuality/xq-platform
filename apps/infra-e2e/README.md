# @experiencequality/showcase-infra-e2e

Real-Docker E2E verification for `@experiencequality/test-infra`. Private app; never published. See `SPEC-test-infra-e2e.md` at the repository root for the design and approval scope.

## Fixture

Exactly 4 containers per run, under a run-unique `COMPOSE_PROJECT_NAME=xq-infra-e2e-<uuid>`:

- `postgres` — `postgres:16-alpine`, seeded by `fixtures/init.sql`, no host port, anonymous data volume.
- `writer` / `reader` — one locally built dummy image (`xq-infra-e2e:<runUUID>`) in two roles. `POST /messages` (writer) and `GET /messages` (reader) share the same PostgreSQL table.
- `xq-gateway` — generated by `xq-infra generate` (`nginx:alpine`), routes `POST /messages` to writer and `GET /messages` to reader; `/writer/*` and `/reader/*` service-name fallbacks also verified.

## Run

```sh
pnpm run test:e2e:infra   # from the repository root
```

Fails (does not skip) when Docker is unavailable. Creates and tears down containers/networks/volumes scoped to the unique compose project; run directories under `$TMPDIR/xq-infra-e2e-*` keep evidence (CLI output, compose configs, resource IDs).
