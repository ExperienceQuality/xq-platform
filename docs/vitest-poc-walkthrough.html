Vitest POC walkthrough

A backend E2E platform with one useful object.

Consumers keep the normal Vitest runner. The platform owns setup, fixtures, HTTP, runtime stubs, isolation, and cleanup.

Foundation and run-level stub lifecycle are working.

02 · Facade design

Everything the test needs, nothing it must assemble.

kittest-scoped facade
apibackend HTTP client
stubruntime service stubs
runIDs and isolation
The facade is public. Transport, registry, process handles, and state files remain internal.
03 · Lifecycle and parallelism

Shared server, isolated intent.

global

Once per run

Start one stub server and provide its URL to workers.

test

One kit per test

Create the facade and bind run metadata.

cleanup

Always close

Clear the test namespace and stop the server.

vitest run → global setup → kit fixture → test → cleanup → global teardown
